# 復習スケジュール管理アプリ

FSRS(Free Spaced Repetition Scheduler)アルゴリズムで、演習問題を解いた日から次の復習日を自動算出するアプリ。

**本番URL**: https://study-scheduler-lemon.vercel.app
(PC・スマホ・iPadのブラウザから利用可。`main` にpushすると自動で再デプロイされる)

---

## Supabaseとは

このアプリの「クラウド側」を担当するサービス。以下を無料枠でまとめて提供してくれる。

- **PostgreSQLデータベース** — 演習項目と復習履歴の保存先
- **認証(Auth)** — メール+パスワードのログイン機能
- **Row Level Security (RLS)** — 「自分のデータしか見えない」制御をDB側で強制する仕組み

サーバーを自分で立てる必要がなく、PCからもスマホからも同じデータにアクセスできる。

## セットアップ手順

### ステップ1: Supabaseアカウントとプロジェクトの作成

1. https://supabase.com/dashboard にアクセスし、GitHubアカウントかメールアドレスでサインアップ
2. `New project` をクリック
3. 以下を入力する
   - **Name**: 任意(例: `study-scheduler`)
   - **Database Password**: 自動生成でOK。**パスワードマネージャーに保存しておく**
     - これはDBに直接SQLで接続する時のパスワード。このアプリの通常利用では使わないが、紛失すると再発行が必要になる
   - **Region**: `Northeast Asia (Tokyo)` を選ぶ(日本から使うので一番速い)
   - **Plan**: Free
4. `Create new project` を押す。プロビジョニングに1〜2分かかる

> **無料枠の注意**: 7日間まったくアクセスがないとプロジェクトが自動的に一時停止(pause)される。ダッシュボードから手動で復帰できるが、毎日使うアプリなら基本的に止まらない。

### ステップ2: テーブルとセキュリティポリシーを作成

1. 左サイドバーの **SQL Editor**(アイコンは `>_`)を開く
2. `New query` をクリック
3. このリポジトリの `supabase/migrations/0001_init_schema.sql` の中身を**全部コピーして貼り付ける**
4. 右下の `Run` を押す(またはCtrl+Enter)
5. `Success. No rows returned` と表示されれば成功

これで以下が作られる。

| テーブル | 中身 |
|---|---|
| `items` | 演習項目(タイトル、タグ) |
| `review_states` | 各項目の現在のFSRS状態(次回復習日、安定度、難易度など) |
| `review_logs` | 復習履歴(いつ・どの評価をつけたか) |

同時に**RLSポリシー**も設定される。これは「ログインしているユーザー本人の行しか読み書きできない」というルールをDB自体に持たせるもの。仮にAPIキーが漏れても他人のデータは読めない。

確認するには左サイドバーの **Table Editor** を開き、3つのテーブルが並んでいて、それぞれに緑の `RLS enabled` バッジが付いていればOK。

### ステップ3: APIキーを取得して .env.local に設定

1. 左サイドバー下部の **Settings**(歯車) > **API Keys** を開く
2. 以下2つをコピーする
   - **Project URL** — `https://xxxxxxxxxxxx.supabase.co` の形式
     - `Settings > General` または `Settings > API` にある
   - **Publishable key** — `sb_publishable_...` で始まる文字列
     - `API Keys` タブにある。まだ無ければ `Create new API keys` を押して作成する

3. プロジェクトフォルダで `.env.local` を作る

```bash
cd C:\Users\gou\dev\claude_test
cp .env.local.example .env.local
```

4. `.env.local` をエディタで開き、値を貼り付ける

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxxxxxx
```

> **キーの種類について**: Supabaseには `publishable`(公開可)と `secret`(秘密)の2種類のキーがある。
> - **publishable key** は`NEXT_PUBLIC_`付きでブラウザに配信されるが、それで問題ない。RLSがすべてのクエリを本人のデータに制限するため。
> - **secret key**(`sb_secret_...`)はRLSを**素通り**して全ユーザーのデータを読めてしまうので、**絶対に`NEXT_PUBLIC_`を付けたり、コードにコミットしたりしない**。このアプリでは使わない。
>
> 古い記事では `anon key` / `service_role key` という名前で説明されていることが多い。これらは上の2つのそれぞれの旧称で、2026年末に廃止予定。新規なら新しい方を使う。

`.env.local` は `.gitignore` 済みなのでGitには含まれない。

### ステップ4: メール確認の設定(任意だが推奨)

デフォルトではサインアップ時に確認メールが飛び、リンクを踏むまでログインできない。自分ひとりで使うなら省略した方が楽。

1. **Authentication** > **Sign In / Providers** > **Email** を開く
2. `Confirm email` を **オフ** にする

オンのままにする場合は、メール内のリンクが `/auth/confirm` に届くよう、**Authentication** > **URL Configuration** で `Site URL` に `http://localhost:3000` を設定しておく。

> 無料枠の組み込みメール送信は1時間あたり数通の制限がある。自分用なのでオフにするのが実用的。

### ステップ5: 起動

```bash
npm install
npm run dev
```

http://localhost:3000 を開く。`/login` にリダイレクトされるので、`新規登録` でアカウントを作る。

## 動作確認の流れ

1. `新規登録` でメールアドレスとパスワードを登録 → ログイン
2. ホーム上部の「今日解いた問題を追加」にタイトルを入れ、出来を選ぶ
3. 「次回は3日後です」と表示され、「すべての項目」に並ぶ
4. 項目名をタップすると復習履歴と、算出された安定度・難易度が見える

Supabase側でも確認できる。**Table Editor** > `review_logs` を開くと、いま記録した行が入っているはず。

## 項目の編集と削除

「すべての項目」の各行から操作する。

- **編集** — その場で入力欄に変わり、タイトル・科目・**次回復習日**を変更できる。詳細ページからも同じ編集ができる。
- **削除** — 確認ダイアログの上で完全に削除する。**復習履歴も一緒に消え、元に戻せない。** 統計の復習回数や日別グラフからも減る。

次回復習日を手で変えても、FSRSの記憶状態(安定度・難易度)は書き換えない。ts-fsrs は経過日数を「前回の復習日から現在まで」で計算しており `due` を入力に使わないため、日付を動かしても次回以降の推定は狂わない。

> `items.is_archived` 列はアーカイブ機能の名残で、現在どこからも使っていない。整理したければ Supabase の SQL Editor で
> `alter table public.items drop column is_archived;` を実行すればよい。

## 使い方

すべてホーム画面で完結する。

**問題を解いたとき** — ホーム上部のフォームにタイトルを入れ、出来を選ぶ。登録と初回評価が同時に済み、次回復習日がその場で決まる。

**復習するとき** — ホームの「今日の復習」に並んでいる項目を解き、出来を選ぶ。

評価は4段階で、これはFSRSアルゴリズムの前提なので減らせない。

| ボタン | 意味 | 新規項目の次回 |
|---|---|---|
| できない | 解けなかった | 1日後 |
| 苦戦 | 解けたが時間がかかった | 2日後 |
| できた | 問題なく解けた | 3日後 |
| 簡単 | 余裕で解けた | 8日後 |

FSRSはこの履歴から「忘れかけたタイミング」を推定し、正解を重ねるほど間隔を伸ばす(できたを繰り返すと 3日 → 14日 → 57日 → 196日)。

毎日ホームを開いて、出ている項目だけ解けばよい。

## 設定

### 目標保持率

復習で出てきたときに、どれくらいの確率で思い出せる状態にしておきたいか。上げるほど間隔が短くなり復習量が増える。既定は 0.90。

| 設定 | 忘れる想定 | 「できた」を続けた場合の間隔 |
|---|---|---|
| 0.85 | 約15% | 4 → 31 → 173 → 773 日 |
| 0.90 | 約10% | 3 → 14 → 57 → 196 日 |
| 0.95 | 約5% | 3 → 6 → 15 → 34 日 |

試験前に取りこぼしを減らしたいなら 0.95、負担を軽くしたいなら 0.85。変更は次回以降の復習から効き、既に決まっている次回復習日は動かない。

### パラメータの個人最適化

FSRSの21個のパラメータを自分の復習履歴に合わせて調整する。`@open-spaced-repetition/binding`(Rust実装)を使う。

大規模な公開データで学習した既定値を**初期値**とし、L2正則化で既定値へ引き戻しながら学習する。データが少ないうちは既定値のままに近く、増えるほど自分向きに寄る。

- **下限は学習アイテム64件。** これ未満だとライブラリ側が学習を省略して初期値を返すため、実行しても意味がない
- 進捗は復習回数ではなく**学習に使えるアイテム数**で数える。同じ項目を2回以上、1日以上あけて復習すると増える。1回解いただけの項目は間隔の情報を持たず学習に寄与しない
- 実行後に logLoss の変化が表示される。いつでも既定値に戻せる
- 目安は月1回程度の再実行

「この環境で最適化が動くか確認する」は、合成データで実行経路だけを検証する自己診断。ネイティブモジュールはビルドが通っても実行時に読めないことがあるため用意した。データも設定も変わらない。

> **実装上の注意**: 不正な入力を渡すとRust側で panic が起き、JavaScriptの例外として捕捉できずプロセスごと落ちる(`Invalid FSRS item: at least one review with delta_t > 0 is required`)。`lib/optimizer.ts` は渡す前に「復習が1回だけの項目」「同日に連打しただけの履歴」を除外している。この検証を外さないこと。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `Invalid API key` | `.env.local` のキーが間違っている。コピー漏れがないか確認し、`npm run dev` を再起動 |
| ログインできるが項目が保存されない | ステップ2のSQLを実行し忘れている。Table Editorでテーブルの有無を確認 |
| 項目を登録しても一覧に出てこない | RLSポリシーが作られていない可能性。SQLを最初から流し直す |
| サインアップ後ログインできない | メール確認が有効なまま。ステップ4で `Confirm email` をオフにするか、確認メールのリンクを踏む |
| `.env.local` を変えても反映されない | 環境変数は起動時に読まれる。devサーバーを一度止めて再起動する |

## 技術スタック

- Next.js 16 (App Router, TypeScript) + Tailwind CSS
- Supabase(PostgreSQL + Auth) — クラウド同期・マルチデバイス対応
- [`ts-fsrs`](https://github.com/open-spaced-repetition/ts-fsrs) — FSRSアルゴリズムの実装

## デプロイは必要か

**必須ではない。** Supabase(DB・認証)は最初からクラウド上にあるので、データはどのみち手元のPCの外に保存される。デプロイするかどうかは「画面をどこから開けるようにするか」だけの違い。

| 使い方 | やること | どこから使えるか | PCの電源 |
|---|---|---|---|
| ローカルのみ | `npm run dev` | そのPCのブラウザだけ | 必要 |
| 同じWi-Fi内のスマホ | `npm run dev -- -H 0.0.0.0` → スマホで `http://<PCのIP>:3000` | 自宅のWi-Fi内だけ | 必要 |
| デプロイ | Vercelにデプロイ | どこからでも(外出先・iPad含む) | 不要 |

PCだけで使うなら`npm run dev`のままでよい。外出先やベッドの中からスマホで復習したくなった時点でデプロイすればいい。あとから移行できるのでいま決める必要はない。

デプロイする場合は、Vercelの環境変数に同じ `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` を設定し、Supabaseの `Authentication > URL Configuration > Site URL` をVercelのURLに変更する。

このアプリを個人で使う限り、**勝手に課金されることはない**。SupabaseもVercelも、無料枠を超えたら請求が来るのではなく機能が止まる仕組みで、有料化にはカード登録とアップグレード操作が明示的に必要。

**Vercel Hobby** — 非商用の個人利用に限り無料。関数実行100万回/月など、個人の勉強アプリでは到達しない水準。超過時は課金ではなく、30日間その機能が使えなくなる。

**唯一の実務的な注意点**: Supabaseの無料プロジェクトは**1週間まったくアクセスがないと自動的に一時停止**される。試験明けや長期休みで放置すると起きる。データが消えるわけではなく、ダッシュボードから復帰ボタンを押せば戻る。
